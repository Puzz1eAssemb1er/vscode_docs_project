# Как работать с этим репозиторием

Этот документ — для тех, кто будет поддерживать или обновлять руководство пользователя. Если вы просто читаете руководство, вернитесь к [user-guide.md](user-guide.md).

## Структура проекта

- `user-guide.md` — руководство пользователя по управлению общими папками.
- `images/` — иллюстрации к руководству.
- `CONTRIBUTING.md` — этот файл.

## Как обновлять документацию

### Оглавление

Якоря в оглавлении формируются автоматически из текста заголовков. Если вы изменили заголовок раздела — не забудьте обновить ссылку в оглавлении, иначе она перестанет работать.

Правила формирования якоря на GitHub:
- пробелы заменяются на дефисы;
- заглавные буквы становятся строчными;
- знаки препинания (кроме дефиса) удаляются;
- русские буквы сохраняются.

Пример: заголовок `## Как создать общую папку` превращается в якорь `#как-создать-общую-папку`.

### Иллюстрации

Все скриншоты и схемы хранятся в папке `images/`. Имена файлов — в нижнем регистре, слова разделяются дефисами.

Пример: `yandex-disk-share-modal.png`.

В тексте изображение вставляется так:

```markdown
![Alt-текст](images/имя-файла.png)

*Рис. N. Подпись к рисунку.*


**Объяснение:**
Это второй вопрос из FAQ, который переехал сюда. Мы не просто говорим «картинки в папке `images`», а задаём **правила именования** и **шаблон вставки**. Это делает документацию предсказуемой: любой, кто добавит новую картинку, будет знать, куда её положить и как назвать. ## Шаг 7. Добавить раздел «Как предложить изменение»

**Что сделать:** добавьте ниже:

```markdown
## Как предложить изменение

1. Создайте ветку от `main`:
   ```bash
   git checkout -b docs/краткое-описание-правки
   ```
2. Внесите правки, закоммитьте с осмысленным сообщением:
   ```bash
   git add .
   git commit -m "docs: краткое описание правки"
   ```
3. Отправьте ветку на GitHub:
   ```bash
   git push -u origin docs/краткое-описание-правки
   ```
4. Откройте pull request и опишите, что и зачем вы изменили.

### Правила хорошего коммита

- Префикс `docs:` для правок документации, `fix:` для исправлений, `feat:` для новых разделов.
- Сообщение — в повелительном наклонении: «исправил», «добавил», а не «исправил бы» или «был исправлен».
- Один коммит — одна логическая правка.
```

**Объяснение:**
Этот раздел — про **процесс работы**, а не про содержание. Он показывает, что вы умеете работать в команде: с ветками, коммитами, пул-реквестами. Даже если репозиторий пока ваш личный, наличие такого описания говорит о понимании workflow. Соглашение о префиксах (`docs:`, `fix:`, `feat:`) — это **Conventional Commits**, отраслевой стандарт. Он пригодится, если вы позже подключите автоматический changelog или CI. И правило «один коммит — одна правка» — базовое требование чистоты истории.

**Напишите «шаг выполнен». Жду.**

## Шаг 8. Сохранить, закоммитить, запушить

**Что сделать:**

1. Сохраните файл: `Ctrl+S`.
2. В терминале выполните три команды по очереди:

```bash
git add CONTRIBUTING.md
git commit -m "docs: добавил CONTRIBUTING с правилами поддержки"
git push
```

3. Обновите страницу репозитория на GitHub (`Ctrl+F5`).
4. Убедитесь, что `CONTRIBUTING.md` появился в списке файлов и открывается.

**Объяснение:**

`git add` — включает файл в следующий коммит. `git commit` — фиксирует изменение с сообщением. `git push` — отправляет на GitHub. Мы используем `git push` без `origin main`, потому что ветка уже привязана к удалённой с прошлого раза. После пуша GitHub покажет новый файл в корне репозитория. Если открыть его через интерфейс GitHub, в правом верхнем углу может появиться упоминание `CONTRIBUTING.md` в контекстном меню — это признак, что GitHub его распознал.
